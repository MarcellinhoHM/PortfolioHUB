1 · Planejamento

Plano + IA como guia

Plano de implantação

Fases, tarefas, critérios de pronto, riscos e rollback. Cada fase virou uma Issue no milestone v2.0.0.

2 · Ambiente e integração

GitHub dedicado ao projeto

  • Publicação pelo Actions no ambiente github-pages, que só aceita a main
  • Site integrado à API do GitHub: repositórios ao vivo, versão em produção, último commit e equipe

3 · Gestão de usuários

Quem pode fazer o quê

Papéis

Admin só para o mantenedor; colaboradores com Triage ou Write, pelo menor privilégio.

Regras da main

Ruleset: PR obrigatório, testes aprovados, conversas resolvidas, sem force push e sem apagar a branch.

CODEOWNERS

Revisor responsável por caminho, com atenção a workflows e à política de segurança.

3 · Segurança

Políticas aplicadas

No GitHub

Secret scanning com push protection, Dependabot (alertas e atualizações), CodeQL, Actions fixadas por SHA, permissões mínimas no token e relato privado de vulnerabilidades.

No site

Content Security Policy sem inline, links externos com noopener, dados da API só via textContent, nenhum segredo no front-end e SECURITY.md publicado.

6 · Desafios superados

O que deu trabalho

Site estático sem backend

O GitHub Actions virou o "backend" na publicação: gera os dados do GitHub sem expor token. A IA roda localmente, nunca no navegador.

CSP rígida

Exigiu tirar todo CSS e JS inline, inclusive dos slides, para não precisar de unsafe-inline.

Único mantenedor

O GitHub não deixa aprovar o próprio PR: bypass que só vale dentro de um PR e fica registrado.

IA com limites

Respostas cortadas no limite de tokens e um anexo que não foi: streaming, limite maior e validar cada recomendação.
